拿到一个陌生平台，怎么一步步做出 005 那样的采集插件；以及想参考别人的下载工具时，怎么把它
拆开、看懂、只取有用的那一点。配套资料：

- `踩坑记录.md`：做之前先过一遍；
- `dyd/方案分析.md`：「寄生浏览器 + 重放请求」和其它方案的完整对比；
- `dyd/分析报告.md`：逆向 DyD 的完整过程记录，本文第三节的实例；
- `dyd/tools/`：解包、去混淆脚本。

> `dyd/` 已经移出工作区，只在 git 历史里。需要时在仓库根目录运行 `git checkout 33ae62f -- dyd`

## 一、总原则：能旁路读，就不重放；能重放，就不逆签名

| 方案 | 怎么做 | 代价 |
|---|---|---|
| **旁路读取**（005 用的） | 挂钩页面自己的 `fetch`/`XHR`，把它收到的响应复制一份 | 只能拿到页面**正在加载**的数据：列表滑到底后不会再请求，丢了只能刷新重来；想要的数据页面不加载就拿不到 |
| 重放请求（DyD 用的） | 截获页面发出的请求（带好了签名和 Cookie），自己再发一遍 | 多一份请求，风控看得到；重放失败时容易静默吞错 |
| 逆向签名 | 自己算出 `X-Bogus`、`a_bogus`、`X-s` 这类签名，脱离浏览器直接调接口 | 签名几周一变，维护成本最高 |

旁路读取对签名改动天然免疫：签名是页面自己算的，我们只读结果。为什么不选另外两种，见
`dyd/方案分析.md`。

**判断一个平台能不能用旁路读取**：你想要的数据（作品列表 + 能下载的直链），是不是在你正常
浏览页面时，页面自己就会去请求。抖音、快手、TikTok 的主页作品列表接口直接带直链，可以；
小红书的主页列表只有笔记 id，直链要逐条打开笔记才有，就只能半旁路（见第五节）。

## 二、分析一个平台的网页

用 Chrome DevTools（F12）就够了。目标是填满这张「平台卡片」：

```text
平台：
主页网址格式：           例：www.douyin.com/user/<sec_uid>
作品列表接口：           URL 特征 / 请求方式 / 分页参数
首屏数据位置：           <script id=...> 或 window.xxx，还是没有
作品对象路径：           例：aweme_list[]
  作品 id：
  作者 id：               用来和主页主人比对
  作者昵称：
  标题 / 时间：           时间是秒还是毫秒
  视频直链：              有几档画质？候选直链在哪个数组
  图集：                  图片数组在哪；有没有「兼容视频」字段
直链域名：               下载要不要 Cookie / Referer
主页里点开作品时网址变化：
其它会干扰的接口：       推荐流、点赞、转发……
```

### 1. 找作品列表接口

1. 登录，打开一个作者主页；
2. DevTools → Network → 过滤器选 **Fetch/XHR**，点清空；
3. 往下滑一屏。新出现的请求里，返回体最大、而且每滑一屏就出现一次的，通常就是作品列表；
4. 拿不准时，用 Network 面板的搜索（Network 面板里按 `Ctrl+F`，会搜请求和响应内容）：
   复制页面上某个作品的标题去搜，能找到包含它的那条响应；
5. 记下：URL 里稳定不变的那段（比如 `/aweme/post/`、`/api/post/item_list`）、是 GET 还是
   POST、POST 的话请求体里有什么（快手 GraphQL 的 `operationName` 在请求体里）。

### 2. 看懂响应结构

- 点那条请求 → **Preview** 展开看结构；右键请求 → Copy → Copy response 存一份到文件里，
  以后字段变了好对比；
- 在一个作品对象里找：作品 id、作者 id、标题、发布时间、视频地址、图片列表、分页游标
  （`cursor`、`has_more`、`max_cursor` 这类）；
- 视频地址常常不止一个：多档画质 × 多个镜像域名。全部收集起来当候选，失败时换着用；
- 图集作品单独找一条看：图片数组在哪，有没有同时带一个视频字段（有的话就是那个「兼容音轨」坑）。

### 3. 找首屏数据

刚打开主页时，第一页作品经常不走接口，而是服务端直接写进 HTML：

- **Elements** 面板里搜 `<script id=`，看有没有一大段 JSON（抖音 `RENDER_DATA` 是 URL 编码过的，
  要 `decodeURIComponent` 再解析）；
- **Console** 里试 `window.__INITIAL_STATE__`、`window.__APOLLO_STATE__` 这类全局变量。

### 4. 判断直链的下载要求

把一个视频直链复制出来：

1. 在**同一个浏览器**的新标签页打开——能播，说明在登录状态下直链本身有效；
2. 在**无痕窗口**打开（不带 Cookie）——如果打不开、或者变成网页，说明下载时要带登录态 Cookie；
3. 看那条请求的 Request Headers 里有没有 `Referer`，响应头的 `Content-Type` 是 `video/mp4`
   还是 `text/html`；
4. 注意直链的**真实域名**。TikTok 就踩过：以为在 `tiktokcdn.com`，实际在 `*.tiktok.com` 子域名下。

结论决定了 background 里的平台配置：`cdnDomains`、要不要 `cookieDomain`、主域名要不要单独一条规则。

### 5. 观察网址怎么变

在主页上依次做：点开一个作品、关掉、切「点赞」「合集」标签、点进另一个作者。每一步看地址栏：

- 点开作品时路径变不变（抖音只加 `?modal_id=`，TikTok 变成 `/@作者/video/<id>`）；
- 标签是用路径区分还是用参数区分（抖音 `?showTab=like`，TikTok `?tab=liked`）。

这决定 adapter 里的 `profileOwner()`（什么算作品页）和 `contextOwner()`（什么还算同一个作者）。

## 三、逆向别人的工具：以 DyD 为例

别人已经做出来能用的下载器，是最快的参考：它踩过的平台接口、字段路径、下载要什么请求头，
都在代码里。完整过程见 `dyd/分析报告.md`，这里是步骤和要点。

### 1. 先认框架

- 安装目录里有 `resources/app.asar`、一堆 `.pak`、`locales/` → **Electron**，业务代码在 asar 里；
- 有 `*.dll` + .NET 特征、Python 打包特征（`python3x.dll`、`base_library.zip`）等，就要换对应的工具，
  本文不展开。

### 2. 解包 asar

asar 是一个简单的打包格式，没有加密：

- Windows：`dyd/tools/Extract-Asar.ps1 -AsarPath app.asar -OutDir out`（纯 PowerShell，不需要 Node）；
- Linux / macOS：`npx @electron/asar extract app.asar out`。

### 3. 找到真正的业务代码

按体积排除：`node_modules`（依赖）、前端打包产物（`dist`、字体）通常占了 99%。看 `package.json`
的 `main` 指向哪里，顺着找到主进程代码。DyD 26MB 的 asar 里，业务逻辑只有 `public/electron/` 下
147KB。

### 4. 去混淆

`_0x3f2a` 这种变量名 + 开头一个巨大的字符串数组 + 一个「解码函数」，就是 javascript-obfuscator。
它只是把字符串藏进数组、打乱顺序，不是加密，可以完全还原：

```bash
node dyd/tools/deobf2.js 混淆的.js 还原的.js   # 跑出解码器，把所有 _0x..(0x..) 换回原字符串
node dyd/tools/polish.js 还原的.js             # 可读性：["prop"] → .prop、0x1f → 31
```

> ⚠️ `deobf2.js` 的原理是**在 Node 的 `vm` 里实际执行混淆代码**，让它自己把解码器初始化好。
> `vm` 不是安全沙箱。来路不明的程序，在虚拟机或用完即弃的环境里跑这一步。

变量名（`_0x4f846d`）还原不了，只能靠读懂后自己起名。

### 5. 读代码：只找三样东西

几千行代码里，下载器真正有用的只有：

1. **接口特征**：搜 `.includes("`、`url.includes`、`/api/`，找它在拦截哪些 URL；
2. **字段路径**：顺着命中分支往下看，它从响应的哪个路径取作品列表、取直链；
3. **下载要求**：下载时带了哪些请求头（Cookie、Referer、特殊签名头），用了哪个域名。

把这三样整理成一份带注释的版本，就够用了。范例：`dyd/src-deobfuscated/service/ks.annotated.js`
（DyD 快手部分的人工注释版）。**只提炼知识，不搬代码**：别人的实现思路可以参考，代码是别人的。

### 6. 注意它有没有把数据发到别处

读的时候顺便看它有没有请求第三方服务器。DyD 的小红书下载会把你的身份 Cookie（`a1`）发到
作者自己的服务器去算签名，视频号整个依赖那个服务器。这种部分我们不复刻。

## 四、接入 005：加一个新平台要改哪些地方

| 文件 | 加什么 |
|---|---|
| `inject.js` | `CONFIGS` 里加一份：`hosts`（页面域名）、`isProfileFeed(url, body)`（只认主页作品列表接口）、`windowKeys` / `scriptIds`（首屏数据） |
| `content/adapter-<平台>.js` | 新建。接口说明在 `content/common.js` 顶部：`parsePayload`、`kindOf`、`profileOwner`、可选 `contextOwner`、`authorFromPage`、验证码识别、主题色。每个 Work 带上 `ownerId` |
| `manifest.json` | `host_permissions` 加页面域名和直链域名；`content_scripts` 加一条（`common.js` → 新 adapter → `panel.js`），`inject.js` 那条的 `matches` 也加上 |
| `background.js` | `PLATFORMS` 加一份：保存目录、`downloaded.txt` 行首前缀、`origin`、`cookieDomain`、`cdnDomains`、`selfDomain`、`ruleBase`（下一个是 5000） |
| `rules.json` | 静态 Referer/Origin 规则，ID 用本平台的段（5001、5002……） |
| `import.js`、`popup.js` | `LABELS` 加平台名；`import.js` 的 `ID_RE` 加作品 id 的格式 |

### 验证清单

1. 打开作者主页，F12 Console 应该有 `[短视频归档][inject] <平台> fetch 已挂钩`；
2. 往下滑，Console 里每次接口回包一行：`… → 解析 N 新增 M 丢弃 K`：
   - 没有这一行：接口没认出来，回去检查 `isProfileFeed`；
   - 解析 0：字段路径不对，导出一份回包对着改 `parsePayload`；
   - 全部丢弃：作者 id 对不上，检查 `ownerId` 和 `profileOwner()` 取的是不是同一种 id；
3. 去「点赞」标签、推荐页、别的作者主页走一圈，确认没混进别人的作品；
4. 在主页里点开一个作品再关掉，确认采集结果还在；
5. 下载：文件进了 `<平台目录>/<作者>/`，没有 `.html`；有的话查 Cookie/Referer 规则
   （service worker 控制台跑 `chrome.declarativeNetRequest.getMatchedRules()`）；
6. 下完看 `downloaded.txt` 有没有、格式对不对。

## 五、未做平台的预研笔记

都在 `dyd/src-deobfuscated/service/` 里，读法见第三节。

### 小红书（已接入 005）

按本文第二节实际分析后接入了，实现见 `005ShortVideoCreatorArchiver/content/adapter-xiaohongshu.js`。分析时用的是
「Console 探针」：在页面里临时挂钩 fetch/XHR，记录 `/api/sns/web/` 下的回包结构，导出给开发者看。结论：

- **主页列表**在 `window.__INITIAL_STATE__.user.notes[0]`（Vue ref，值在 `_rawValue` 上），滑动时页面自己往里追加，
  只有笔记 id、标题、类型（`normal` / `video`）、作者 `userId`、`xsecToken`，**没有地址**；
- **点开笔记**（弹出层，网址变成 `/explore/<id>`）时页面自己请求 `/api/sns/web/v1/feed`，`note_card` 里有完整
  `image_list` 和 `video.media.stream`；但这个接口要 `X-s` 签名，自己调不了；
- **笔记网页** `GET /explore/<id>?xsec_token=…` 不要签名，服务端渲染的 HTML 里内嵌了整篇笔记
  （`__INITIAL_STATE__.note.noteDetailMap`，注意它是 JS 字面量：有 `undefined`、`new Map([])`，要先替换再
  `JSON.parse`），实测每篇 0.4~0.6 秒。005 用的就是这个：列表旁路读，详情按 1~2 秒一篇请求笔记网页。
  最早的版本是在页面上逐篇点开弹出层再旁路读 `/feed`，能用但太慢、太「像机器人」，被这个替代了；
- **原图**：`https://sns-img-bd.xhscdn.com/<fileId>`，无签名、无水印，分辨率比接口给的 `url_default` 高；
- **视频**：`video.media.stream` 按编码分组（`EF4`、`EF5`……），每档有 `master_url` 和不带签名的 `backup_urls`；
  DyD 用的 `consumer.originVideoKey` 已经没有了；
- **列表是虚拟列表**：同一时间只有 30 来张卡片 `section.note-item[data-note-id]` 在页面里；但列表数据在
  页面状态里是完整累积的，读状态就不受虚拟列表影响。

DyD 的做法（调页面签名函数 `window._webmsxyw()` 自己发详情请求，`X-S-Common` 交给作者自己的服务器算，
还把身份 Cookie `a1` 发过去）没有采用。

### 视频号（`vx.js`）

不是网页采集。DyD 依赖作者自己的远程服务（绑定 id → 拉取转发过来的视频消息），视频本身前
128KB 用服务器给的密钥（Isaac64）做了异或加密，下载后再解密。离开那个服务无法复现，仅作了解。
