# DyD 下载器 —— 技术方案分析

> 对象：`DyD-win-3.0.3-ia32`（抖音/快手/小红书/TikTok/视频号 短视频下载器）
> 配套：`分析报告.md`（逆向细节）、`src-deobfuscated/`（去混淆源码）、`src-deobfuscated/service/ks.annotated.js`（快手逻辑注释版）
> 环境说明：本文不受 Windows 环境限制影响，面向在 macOS 上重建/改造的场景。

---

## 一、原软件用的是什么方案

一句话：**寄生在一个真实的浏览器窗口里，在"请求发出前"截获官方接口调用，然后用 HTTP 客户端把这次调用原样重放一遍，从 JSON 响应里挖直链。**

### 1. 运行形态

- 框架 **electron-egg**（Electron + Nuxt2 前端 + ee-core 的 controller/service/addon 结构）。
- 前端（`public/dist`）只是 UI，通过 IPC 把 `{platform, type, url}` 丢给主进程。
- 主进程 `controller/main.js` 按 `platform` 分发给 `service/{dy,ks,xhs,tk,vx}.js`。

### 2. 采集机制（核心）

`service/collection.js` 负责开一个**独立的** `BrowserWindow`（注意：不是主窗口，创建时没传 `webPreferences`，所以用的是 Electron 默认的 `contextIsolation:true / nodeIntegration:false`），加载用户粘贴的主页/作品链接，挂三个钩子：

| 钩子 | 用途 |
|---|---|
| `session.webRequest.onBeforeSendHeaders` | **请求发出前**拿到 `url` / `requestHeaders`（含 Cookie）/ `uploadData`（POST body） |
| `webContents.on('will-redirect')` → `urlInterceptor` | 改写 URL（如抖音 `com/note/` → `com/video/`、`modal_id=` → `/video/`） |
| `webContents.on('did-finish-load')` | 注入几个提示浮层 `#dydTip1/2/3` |

拿到请求信息后，各平台 service 在钩子回调里**用 axios 重放同一个请求**（`delete Accept-Encoding` 拿明文，`Referer` 追加随机 `?r=xxxxxx`），从响应里解析。快手有 5 个分支：

| type | 命中条件 | 取值路径 |
|---|---|---|
| home | `com/graphql` 且 body 含 `photoContent on PhotoEntity` | `data.data.visionProfilePhotoList.feeds[]` |
| solo | URL 含 `short-video` / `com/f/` | 不重放，`executeJavaScript` 读 `window.__APOLLO_STATE__.defaultClient`，找 key 含 `VisionVideoDetailAuthor` / `VisionVideoDetailPhoto` |
| home | `profile/public?` | `data.data.list[]` |
| solo | `profile/feedbyid?photoId` | `data.data.currentWork` |
| solo | `chenzhongtech` + `photo/info` | `data.atlas.list` + `data.atlas.cdn[0]` |

### 3. 下载层

- 视频：`electron-dl` 的 `download()`（走 Chromium 下载管理器），失败自动换下一条直链重试。
- 图集 / 封面：自写的 `addon/axDownloader`（axios 流式写盘，支持代理、取消、批量）——**这层是纯 Node，无 Electron 依赖**。
- 优先 `photoH265Url`，回退 `photoUrl`；直链是 `*.kwaicdn.com` 带时效签名的地址。

## 二、这个方案的优点

1. **不用逆签名，维护成本极低。**
   抖音的 `X-Bogus` / `a_bogus` / `_signature` / `msToken`、快手的 `__NS_sig3` / `kpn` / `did` 这些反爬参数，全部由**真实网页自己生成**，工具只是把带齐参数的请求转发一遍。别人逆一版签名可能几周就失效，这个方案对签名改动天然免疫。

2. **天然带登录态。**
   采集窗口里用户自己登录，Cookie 随 `requestHeaders` 一起被截获并重放 → 直接突破"未登录只能看前 20 条"，能拿到私密/完整数据。

3. **风控参数搭便车。**
   `did`、设备指纹、`kpf/kpn`、时间戳 nonce 等都在真实请求里，重放时一并带上，比手搓请求更容易过第一层校验。

4. **多平台复用一套基建。**
   `collection.js` 的窗口 + 三钩子是通用的，每个平台只写"命中哪个 URL、从哪个字段取直链"，加平台很快。

5. **验证码优雅降级。**
   弹验证码时窗口是可见的，用户手动过一下就能继续，不需要打码服务。

6. **跨平台。** Electron 一套代码 Win/Mac/Linux 都能跑。

## 三、这个方案的局限

### 1. 与"网站内部接口"强耦合，极脆（**这次快手失效的根因**）

命中逻辑写死了字符串和路径：`photoContent on PhotoEntity`、`visionProfilePhotoList.feeds`、`__APOLLO_STATE__.defaultClient`、`VisionVideoDetailPhoto`……
快手 Web 端任意一次改造（改 GraphQL fragment 名、换接口、迁出 Apollo、字段改名）都会让某个分支**再也命中不了**，而且——

### 2. 静默失败

所有分支的 `catch` 都是 `catch(e){}` 或 `catch(e){console.log(e)}`，没有落盘日志、没有上报前端。表现就是"采集 0 个"，用户完全不知道是接口变了、被风控了、还是没登录。

### 3. "重放"本身是设计缺陷

- 它**不读真实响应**，而是发**第二个一模一样的请求**。于是每翻一页，快手就收到**两次**近乎相同的请求，其中一次的 `Referer` 还被塞了个畸形的 `?r=xxxxxx`。
- 这个重放请求来自 **Node 的 TLS 栈**，JA3/ALPN 指纹与 Chrome 不同；没有 HTTP/2 多路复用、头顺序不一致。对有行为风控的快手来说，这几乎是在自曝。
- 存在竞态：重放可能比真实请求先到 / 拿到不同分页游标。

### 4. 自动化痕迹（虽然比 Playwright 轻，但不是零）

采集窗口是默认隔离的，所以 `window.process` 这类 **不会**泄漏给目标站；`navigator.webdriver` 也是 `false`（没加 `--enable-automation`、没挂 CDP）。但仍有可辨识点：

| 痕迹 | 说明 |
|---|---|
| **UA / Client Hints 不一致** | UA 被硬改成 `Chrome/126.0.0.0`，但 `Sec-CH-UA` 品牌里是 `"Chromium"` 而非 `"Google Chrome"`，`navigator.userAgentData` 也没同步 → 经典 bot 信号 |
| UA 版本会过期 | `Chrome/126` 写死在 `collection.js`，随时间越来越可疑 |
| `--ignore-certificate-errors` | 全局关掉证书校验（`collection.js:18`），不可被页面直接检测但削弱安全 |
| 注入的 `#dydTip1/2/3` 浮层 | 加载后往 DOM 里塞固定定位的中文提示 div，枚举 DOM 能发现 |
| 非人类滚动 | `scrollToBottom` 一次 `scrollTo(0, scrollHeight)` 跳到底；无鼠标轨迹、无停顿 |
| 干净 profile | 无历史、无其它 Cookie、无扩展、`window.chrome.runtime` 形态与真 Chrome 有差异 |

### 5. 功能不完整

- 快手 kind 101 / 102 的**图文（非视频）分支是空的 `else {}`** —— 主页/单条快手图文本来就取不到图片 URL。
- `photoH265Url` 有时需要额外 `Range` / `Referer` / 时效 token，403 时只能靠 `downloadV` 换 `photoUrl` 兜底。

### 6. 必须有头、要人盯着

采集窗口必须可见，要手动滚动加载、手动过验证码，无法真正无人值守 / 批量跑。

### 7. 交付臃肿 + 假保护

为了 ~147KB 的业务逻辑，打包了 134MB 的 Electron+Chromium+Nuxt。`打包Win.bat` 里的 `npm run encrypt` 只是 javascript-obfuscator，几分钟就能还原（见 `tools/deobf2.js`），给了虚假的安全感。

### 8. 其它

- 单个 `collection` 窗口被所有平台共用，切换平台时监听器可能串味。
- 视频下载依赖 `this.app.mainWindow`（electron-dl 需要一个 BrowserWindow 宿主），无法脱离 Electron。

## 四、和其它方案的对比

| 方案 | 是否需逆签名 | 对目标站的痕迹 | 脆性 | 能否无头/批量 | 备注 |
|---|---|---|---|---|---|
| **原方案：Electron 窗口 + onBeforeSendHeaders + axios 重放** | 否 | 中（UA/CH 不一致、重放双请求、注入 DOM） | **高**（写死内部接口路径） | 否 | 现状 |
| 纯 API + 自己实现签名 | **是** | 低（可仿 Chrome 指纹） | 高（签名一变就废） | 是 | 维护地狱 |
| Headless Chromium + stealth（Playwright/Puppeteer + 反检测补丁） | 否 | 中高（`Runtime.enable` getter 泄漏、headless WebGL/字体、`navigator.webdriver`） | 中 | 是 | 与风控持续猫鼠 |
| **CDP 挂真实 Chrome，只 enable `Network` 域** | 否 | **低**（用真 user-data-dir，不加 `--enable-automation`，不 enable `Runtime`/`Page`，`webdriver` 仍 false） | 中（仍解析内部接口，但可只读真实响应，不重放） | 半自动 | 脚本化的最佳折中 |
| **本地 MITM 代理**（whistle / http-mitm-proxy，Node） | 否 | **接近零**（页面 JS 零改动，TLS 是真 Chrome 的 JA3） | 中（解析内部接口响应） | 半自动 | 一次性装 CA 证书；抓取层最稳 |
| **MV3 浏览器扩展**（在日常 Chrome 里） | 否 | **零**（就是用户本人在浏览，真指纹真历史真 Cookie） | 中 | 否（人在刷） | content script 读 `__APOLLO_STATE__` 或 tee `fetch`，直链 POST 给本地 Node 下载服务 |

关键结论：

- **"截获直链"这一步无法脱离浏览器**（除非自己实现签名）。真正省心的做法是**搭在用户真实的浏览器上**，而不是造一个新的自动化浏览器。
- **重放**应改为**读真实响应**（CDP `Network.getResponseBody` / 代理抓包 / 扩展 tee），既减一半请求，又消除 Node TLS 指纹和 Referer 畸形这两个风控触发点。
- **拿到直链之后的下载是纯 Node 的**，`src-deobfuscated/addon/axDownloader/index.js` 可以直接复用：`*.kwaicdn.com` 的签名 URL 通常带个 `Referer` 就能下，不需要登录态。

## 五、在 macOS 上重建的建议

1. **抓取层**二选一：
   - 要脚本化 → CDP 挂真实 Chrome（`chrome-remote-interface`），只 `Network.enable`，按 `ks.annotated.js` 的 5 个分支匹配 `visionProfilePhotoList` 等响应，用 `Network.getResponseBody` **读真实响应**（不重放）。
   - 要最抗风控 → `whistle` 起本地代理，规则匹配同样的响应体。
2. **归一化层**直接照搬 `common.pkgTask` + `handleFeed` 的字段映射（`src-deobfuscated/common.js` / `service/ks.js`）。
3. **下载层**直接用 `addon/axDownloader`（纯 axios，去掉 electron-dl 那条路径）。
4. **补 3 个原版缺陷**：图文分支补全、`catch` 打日志、UA/CH 用真实 Chrome 的值（CDP/代理方案天然就是真值）。
5. 快手接口若已改版：在真实浏览器里翻一次主页，抄下当前的接口 URL / operationName / 响应结构，替换掉 `ks.annotated.js` 分支 A / kind 101 的字段路径即可。
