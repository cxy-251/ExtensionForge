# 快手创作者作品归档助手

Chrome Manifest V3 扩展。在**你自己的浏览器**里、你正常浏览快手时，旁路读取页面
自身发出的作品接口，抓取视频 / 图集直链并交给浏览器下载。支持导入一份创作者
主页列表，逐个自动滚动采集、连续归档。

> 设计取舍见 `../../dyd/方案分析.md`。核心一句话：**不造自动化浏览器、不重放请求、
> 不逆签名**，只在真实会话里旁路读响应，因此对快手侧几乎没有额外自动化痕迹。

---

## 安装与更新

1. 打开 `chrome://extensions`；
2. 打开右上角「开发者模式」；
3. 点「加载已解压的扩展程序」，选择本目录 `002KuaishouCreatorArchiver`；
4. 改代码后：在扩展卡片点「重新加载」，再刷新已打开的快手页面。

## 用法一：单个创作者（页面面板）

1. 打开任意 `https://www.kuaishou.com/profile/<id>` 主页；
2. 右下角出现「快手归档助手」面板；
3. 向下滚动，或点面板里的 **自动加载并采集**，作品会持续被采进来；
4. 点 **下载全部**，文件落到 `下载目录/快手/<作者>/` 下；
   - 视频：`<日期>_<标题>.mp4`
   - 图集：`<日期>_<标题>/01.jpg 02.jpg …`
5. **复制直链** 可把当前已采集的所有直链拷到剪贴板，自己拿别的工具下也行。

面板按钮：

| 按钮 | 作用 |
|---|---|
| 自动加载并采集 | 自动滚动到底，连续 3 轮没有新作品就停；再点一次可手动停止 |
| 下载全部 | 把当前已采集的作品全部加入下载队列 |
| 复制直链 | 复制所有视频 / 图片直链（每行一个） |
| 清空 | 清掉当前页面已采集的列表（不影响已在下载的） |
| 每条右侧 ⬇ | 只下载这一条 |

## 用法二：批量列表（控制台）

工具栏图标的弹窗只有一个「**打开控制台**」按钮 —— 点它打开 `app.html` 标签页，
列表 / 连续采集 / 授权 / 队列全在这个标签页里。**这个标签页保持打开**，连续模式就一直跑。

1. 弹窗 →「打开控制台」；
2. （可选但推荐）**授权下载根目录**：点一次，在系统对话框里指到你**浏览器默认下载目录**
   （不新建、不移动任何东西）。授权后就能读写 `downloaded.txt`，见下方「去重」；
3. **导入 kuaiChannels.txt**：每行一个 `https://www.kuaishou.com/profile/<id>`，
   重复导入自动去重合并、保留进度；
4. 设「每位作者滚动上限」「作者之间等待秒数」，点 **开始连续模式**；
5. 逐个后台开创作者主页 → 自动滚动采集 → 只下没下过的 → 关页 → 随机等待 → 下一个；
6. 撞验证码会停，去弹出的标签页手动过，回控制台点 **继续**（此时「开始连续模式」按钮变「继续」）。

单次：**打开下一个** 只处理列表里的下一位，不连续。

## 下载队列

- **并发数**：同时下载的文件数（默认 3）。
- **保存目录前缀**：默认 `快手`，即文件落在 `<下载目录>/快手/<作者>/…`。
  视频走 `chrome.downloads`，**只能是「下载目录」下的子文件夹**；要换根位置改
  Chrome 下载设置（`chrome://settings/downloads`），比如 `E:\网红库\`，
  然后把控制台里「授权下载根目录」指到同一个地方。
- 每条作品带多个候选直链（优先带 `pkey` 的 CDN 通用签名链），失败自动换下一个。
- **暂停队列 / 清空队列** 独立于采集。

### 已下载去重（按 videoId，不看文件在不在）

两处记录，互为镜像：

| | 是什么 | 谁维护 | 作用 |
|---|---|---|---|
| `chrome.storage` 的 `dl:<id>` 索引 | 磁盘上的浏览器数据库（不是内存），扛得住关浏览器、重载扩展 | background 每完成一条就写 | **扩展实际拿它判断跳不跳过** |
| 每个作者文件夹的 `downloaded.txt` | 纯文本，每行 `kuaishou <id>`，**yt-dlp `--download-archive` 兼容** | 控制台页（需先授权目录）在 `dl:` 变化后写回，用 File System Access **直接写**，下载栏不闪 | 可移植、可读、可 git 的持久记录；跨机器迁移就靠它 |

- 开始连续模式前，控制台会先把授权目录下所有 `<前缀>/*/downloaded.txt` 读进 `dl:` 索引
  （也可随时点「立即同步磁盘」）。所以**换电脑后**：授权一次目录 → 自动扫回全部已下记录。
- 没授权目录也能用，只是只有 `dl:` 索引、不写 txt。
- 面板里已下的作品打灰标「已存」；「下载全部」和连续模式默认跳过；面板勾
  「包含『已存』」可强制重下，单条 ⬇ 永远强制下。
- 控制台「重置记录」只清 `dl:`/`arc:` 索引，**不动磁盘上的 txt**（可「立即同步磁盘」找回）。
  「导入 downloaded.txt」手动喂一个或多个 txt（也可拿现成 yt-dlp archive）。

## 工作原理

```text
inject.js   （MAIN world, document_start）
   挂钩 window.fetch / XMLHttpRequest，把 /graphql、profile/public、feedbyid、
   photo/info 等响应体抄一份 postMessage 出去。不改写、不重放。

content.js  （ISOLATED world）
   收响应 → 解析成「作品」（多字段兜底：photoH265Url / photoUrl / mainMvUrls…，
   图集走 ext_params.atlas）→ 去重入库 → 渲染面板 / 自动滚动 / 验证码识别
   → 把作品结构发给 background。

background.js（service worker）
   作品 → 下载项展开（多候选直链）→ 按并发上限调 chrome.downloads → 失败换链/重试 →
   完成后写 dl:<id> 和 arc:<作者> 索引。

app.js（控制台标签页）
   创作者列表；连续模式调度（逐个开标签页、发指令、等回报、关标签页、随机间隔）；
   File System Access 磁盘层（授权根目录 → 开跑前把 downloaded.txt 读进索引，
   arc:<作者> 变化时把该作者的 downloaded.txt 写回）；下载队列监控。

popup.js
   工具栏弹窗，只是「打开控制台」入口 + 队列一览。

rules.json （declarativeNetRequest）
   给发往快手 CDN（kwaicdn / yximgs / kwimgs / ndcimgs / oskwai）的请求补 Referer / Origin，
   避免直链 403。
```

解析分支对应老工具 DyD 的 `service/ks.js`（`../../dyd/src-deobfuscated/service/ks.annotated.js`），
但字段读取做了多名兜底，并在所有已知分支都不命中时对整个 JSON 做一次
「长得像作品的对象」兜底扫描。

## 文件结构

```text
manifest.json        清单：两个 content script（MAIN 抓包 + ISOLATED 逻辑）、popup、DNR 规则
inject.js            页面主世界：fetch / XHR 旁路抓包
content.js/.css      采集解析、页面面板、自动滚动、验证码识别、下发下载
background.js        下载队列（多候选直链、并发、重试、落盘续跑）+ dl:/arc: 索引
app.html/.css/.js    控制台标签页：列表 + 连续采集 + File System Access 磁盘层 + 队列
popup.html/.css/.js  工具栏弹窗：打开控制台 + 队列一览
rules.json           给快手 CDN 直链补 Referer
README.md / PRIVACY.md
```

## 排查：面板出来了，但「采集 0 条」/ 按钮点着没反应

按钮其实都在响应（点一下看 F12 Console 会打印 `[快手归档] 点击按钮 …`），
「没反应」通常是**一条作品直链都没采到**，所以下载/复制自然是空的。按这个顺序查：

1. **点面板里的「统计检测」**。它会告诉你：已采集直链几条、页面上可见作品约几个、
   收到接口回包几次。
2. **点「调试信息 ▸」** 展开。
   - **一条回包都没有** → `inject.js` 没抓到请求。多半是没「重新加载扩展 + 刷新页面」；
     或 Chrome 版本 <111 不支持 MAIN world。F12 Console 应能看到
     `[快手归档][inject] fetch 已挂钩`，没有就是注入没生效。
   - **有回包，但每条都是 `✗ +0/0`**（解析出 0）→ 快手接口结构变了。把其中一条
     标 `·` 或 `✗` 的响应，在 Console 里 `右键 → Store as global variable` 看结构，
     或直接把那几条 URL 发我，我改 `content.js` 里的 `parsePayload` / `fromPhoto`。
   - **有 `✓` 行但列表还是空** → 采到了但被「既无视频直链又无图片」过滤掉了，
     多半是直链字段改名，同样把响应结构发我。
3. 确认你在这个页面**已登录快手**——未登录时profile页可能根本不请求作品列表。



- **依赖快手 Web 接口结构**。快手改字段 / 换接口，某分支就可能采不到；已尽量做
  兜底，但真失配时需要照当前响应改 `content.js` 的 `parseEntry` / `fromPhoto`。
  排查：`chrome://extensions` → 本扩展「Service Worker」/ 页面 Console 看解析结果。
- **要人在场**：连续模式仍是打开真实标签页 + 自动滚动，快手风控可能限速 / 弹
  验证码。把「作者之间等待」调大、滚动上限调小能缓解。
- **自动滚动有痕迹**：虽然加了随机间隔和回滚抖动，但连开大量主页仍不等于真人。
  建议分批跑，别一次几千个。
- **保存路径受限**：视频走 `chrome.downloads`，只能相对「下载目录」，不能任意绝对路径。
  `downloaded.txt` 走 File System Access，能写进你授权的那个目录树。
- **控制台标签页关掉 = 连续模式中断**（下载队列不受影响，会继续）；下次打开控制台
  会把卡在 running 的作者复位成待处理，可继续跑。
- **File System Access 只在控制台标签页有效**：service worker / content script 用不了；
  控制台没开时，只有 `dl:` 索引在维护，`downloaded.txt` 等下次开控制台再同步。
- **图文分支**：主页 GraphQL 若不返回 `imgUrls` / `atlas`，图文作品可能只拿到封面。
- 未上架，也不建议上架（Web Store 一般不收此类扩展），仅开发者模式自用。

## 建议手动验证清单

- 打开一个创作者主页：面板是否出现，手动滚动时计数是否增长；
- 点「自动加载并采集」：能否滚到底并在无新增后自动停；
- 点「下载全部」：`下载目录/快手/<作者>/` 下是否出现 mp4 / 图集文件夹；
- 打开一条图集作品页：是否识别为「图集」并能下多张图；
- 弹窗导入 `kuaiChannels.txt`：计数正确、重复导入不重复；
- 连续模式（标签页面板）：逐个处理、间隔生效、进度条推进；
- 人为触发验证码：是否停下并可「继续」。

## 隐私

见 [PRIVACY.md](./PRIVACY.md)。简述：只在快手域名下运行；只读页面已有的接口响应；
不读 Cookie、不额外发请求到快手、不上传任何数据；创作者列表和下载进度只存在本
机 `chrome.storage.local`。
